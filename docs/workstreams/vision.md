### Frame/clock integration rules (final)

`onStream` lends the actual station MediaStream; do not stop its tracks from staff subscribers. Stop/loss/unmount calls `onStream(null)`. A remote browser cannot consume this object; main owns real transport. Do not start a second capture from staff.

`onFrame` **synchronously borrows** the camera-owned bitmap. Sample synchronously; start `createImageBitmap(frame.frame.image)` before returning if asynchronous work needs an independent clone. The producer closes the original in `finally`, even if a consumer throws. Do not retain, transfer or close the original. **Do not pass it directly to `publishBoundFrame`, which also owns/closes its input.** A synchronous adapter can invoke sensing runtimes directly, or main can supply a separate cloned/owned bitmap to the existing frame bus. `onBindings` never contains descriptors or video. `context.nextSeq` must be the binding-stream allocator, independent of pose/rPPG/breathing streams; `context.getSyncId()` must report the current valid sync or null.

Vision outputs `identityStamp`, optional adapter-supplied face-skin ROIs, and a conservative face-box edge-displacement rate in face widths/second derived from distinct same-epoch detections. After confirmation/reset, face motion stays null until a second same-epoch inference. `poseStamp`, `torso`, and `poseMotion` remain null; main must enrich the borrowed BoundFrame from a fresh same-epoch pose result before feeding channels that require pose. No made-up torso/skin mask is supplied. Empty skin ROIs or missing pose/motion should be rejected by sensing. Cached identity metadata expires after 500ms; it cannot prove nobody entered between detector calls. Actual low latency/cadence/framing still require the combined device probe.
